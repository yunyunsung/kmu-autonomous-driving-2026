|---|---|---|

| 컴퓨터 | reComputer Super J4012 (Jetson Orin NX 16GB, JetPack 6 / Ubuntu 22.04) | 기본 Ryzen 보드에서 교체 ([06](06-tensorrt-deployment.md)) |

## 기동 체크리스트

ROS2 노드만 띄우면 **차가 움직이지 않습니다.** 대회 당일에도 순서가 꼬이면 출발 1분 제한에 걸릴 수 있어
체크리스트로 관리했습니다.

1. Docker(ROS1) 컨테이너 기동
2. `ros1_bridge` 프로세스 확인 (좀비 `dynamic_bridge`가 남아 있으면 정리)
3. ROS1 쪽 `vesc_speed_bridge.py` (실측 속도를 `Float32`로 변환)
4. `ros2 launch track_drive track_drive.launch.py`
5. 기동 로그에서 확인: 차선 인식이 `dl` 백엔드로 떴는지(아니면 `hough`로 폴백), TwinLiteNet+ 프로바이더가
   `TensorrtExecutionProvider`인지, `[LAP] 누적=` 값이 움직이는지(IMU 생존)

종료는 반드시 `Ctrl+C`로 합니다. `Ctrl+Z`나 터미널 강제 종료는 `usb_cam`을 좀비로 남겨 다음 실행에서 카메라가
안 잡힙니다.

```bash
sudo fuser -k /dev/video0   # 카메라만 문제일 때
```

## 센서별 함정

### VESC 속도는 실제보다 5~11% 높게 나온다

줄자로 잰 지상 속도와 비교한 결과입니다. 보정 게인을 바꿀지는 결정하지 못했고, 속도 환산은 줄자 실측
회귀값(`METERS_PER_SPEED_UNIT=0.0848`)을 기준으로 삼았습니다.

### IMU는 처음부터 고장나 있었다

`track_drive`는 처음부터 `/imu`를 구독했지만 하드웨어가 고장나 **한 번도 값이 들어온 적이 없었습니다.**
에러 없이 `imu_yaw`가 초기값에 고정됐고, 바퀴 수 카운트가 계속 0이었던 이유가 이것이었습니다. 8/6에 수리하고,
실차 워크스페이스에만 있던 `xycar_imu` 패키지를 저장소로 편입했습니다(launch 파일 오타 2건도 함께 수정).

### 출발할 때 툭툭 끊기는 증상은 끝내 못 잡았다

- 1차 가설(8/7): 가속 중 전류 스파이크 → 배터리 저전압 보호(LVC) 트립. 가속 램프를 0.85 → 0.4로 완화.
- 2차 가설(8/17): 20Hz 계단식 램프가 정지마찰 구간에 4틱 머무는 동안 가장 큰 전류가 흐름. 첫 틱에 바로
  3.0으로 점프하는 `SPEED_KICK_START` 도입.
- 실차 재검증(8/18): 개선 없음. 출발 성공률이 오히려 떨어진 세션도 있었습니다.

소프트웨어로 할 수 있는 건 다 해본 상태라, **배터리 내부저항, ESC 보호 임계값, 커넥터 접촉** 쪽을 의심하고
정상 배터리팩으로 A/B 비교하는 것을 다음 점검으로 남겼습니다.

## 원격 접속 (헤드리스 운용)

대회장과 연구실에서 차에 모니터를 달 수 없어 원격 데스크톱이 필수였습니다.

| 시도 | 결과 |
|---|---|
| NoMachine | 유료화(v10+)로 대체 필요 |
| xrdp | 헤드리스에 맞는 방식이지만 최종적으로는 미사용 |
| **x11vnc + HDMI 더미 플러그 + TigerVNC** | 채택. 이더넷 직결(`192.168.100.x`) |
| 교내 Wi-Fi로 VNC/SSH | 학교 네트워크가 원격 데스크톱 프로토콜을 차단 (TCP reset) |
| **Jetson Wi-Fi 핫스팟** | 채택. 노트북이 차량 핫스팟(`10.42.0.1`)에 붙어 VNC |
| 핫스팟 + USB 동글로 동시 인터넷 | 드라이버 설치는 성공했으나 이후 스캔 불가 상태 반복 → 포기 |

x11vnc 쪽에서 알아둘 것:

- x11vnc는 **이미 떠 있는 화면**을 공유하므로 모니터가 없으면 공유할 화면 자체가 없습니다. HDMI 더미 플러그로
  그래픽카드가 모니터가 있다고 믿게 만들었습니다.
- 실제 모니터와 더미 플러그를 **세션 중에 바꿔 끼우면** 핫플러그 신호 때문에 연결이 끊깁니다. 소프트웨어로는
  못 막으니 더미만 꽂고 부팅합니다.
- `-noxrandr` 옵션으로 해상도 변경 이벤트에 의한 끊김을 막았고, systemd 서비스로 자동 재시작하게 했습니다.
- USB Wi-Fi 동글(RTL88x2bu)은 오래된 드라이버 저장소에서 aarch64 빌드 오류가 나 다른 저장소의 드라이버로
  설치했지만, 이후 PHY 초기화 경고와 함께 스캔이 안 되는 상태가 반복됐습니다. USB 허브를 여러 단 거친
  전력 부족 또는 동글 불량으로 추정합니다.

## 빌드 환경에서 막혔던 것

| 증상 | 원인 | 해결 |
|---|---|---|
| `colcon build`가 `setup.py` 없다고 실패 | `package.xml`만 있고 파이썬 패키지 마커 누락 | `setup.py`/`setup.cfg`/`resource/`/`__init__.py` 추가 |
| 같은 패키지명 중복으로 빌드 실패 | `track_drive`가 워크스페이스 두 곳에 존재 | 한 곳만 남김 |
| `imu_node`가 `numpy has no attribute 'float'` | apt 구버전 `transforms3d` vs 최신 numpy | `pip3 install --user --upgrade transforms3d` |
| YOLO 가중치 경로가 `build/`로 잡힘 | `--symlink-install` 링크를 `abspath()`가 안 풂 | `realpath()`로 교체 |
| `usb_cam`이 장치를 못 열고 SIGABRT | 기본 설정이 `/dev/video0` | launch에서 `/dev/videoCAM` 지정 |
| `SPEED_NORMAL=0`이면 노드가 죽음 | 속도 계산의 분모로도 쓰임 | 저속 테스트는 5~10 같은 양수로 |
