# 08. 캘리브레이션과 실측값

설계 일지에서 가장 잘 지킨 원칙은 **실측값과 설계값(임의로 고른 값)을 구분해 적는 것**이었습니다.
섞이면 아직 검증 안 된 값을 검증된 값으로 착각하고 재확인을 건너뛰게 됩니다.

## 실측값

| 상수 | 값 | 측정 방법 |
|---|---|---|
| `LANE_WIDTH_M` | 0.40m | 흰 선~흰 선 80cm 실측, 노란 중앙선이 정중앙 |
| `VEHICLE_WIDTH_M` / `LENGTH_M` | 0.31m / 0.64m | 자이카 본체 실측 |
| `WHEELBASE_M` | 0.335m | 앞뒤 차축 간격 줄자 실측 (초기 0.26은 오류) |
| `OBSTACLE_VEHICLE_WIDTH_M` | 0.24m | 고정장애물 20×41cm, 방해차량 28×54cm 폭 평균 |
| `LIDAR_ANGLE_OFFSET_DEG` | 80° | 정면에 사람을 세우고 컴퍼스로 확인 (7/22). 이후 88~89 관찰, 미반영 |
| BEV 소스 4점 | TL(246,257) TR(455,257) BR(635,333) BL(60,333) | 라이브 카메라에서 클릭, 실측 폭 0.8m·길이 1.0m |
| `METERS_PER_SPEED_UNIT` | 0.0848 m/s | speed 5/10/15 각 3~4회, 줄자 + 구간 타이밍, 원점 고정 회귀 |
| `VESC_SPEED_TO_ERPM_GAIN` | 4614.0 | VESC 드라이버 설정값 그대로 |
| YOLO 박스 면적 임계값 (B1/B2/B3) | 각각 실측 | 전용 디버그 창으로 트리거 거리에서의 박스 크기 측정 (8/24) |

### 속도 실측 방법

트랙에 줄자로 40cm 간격 표시를 하고, 차가 각 표시를 지날 때 Enter를 눌러 시각을 찍었습니다
(`measure_speed_calibration.py`).

- 첫 구간은 가속이 섞이므로, 연속 두 구간 속도가 12% 이내로 비슷해지는 지점부터 정속 구간으로 봅니다.
- 사람 반응 시간 오차(0.1~0.2초)가 구간별로 크기 때문에, 정속 구간의 (시각, 누적거리) 점들을 한 번에
  최소자승 회귀해 기울기를 속도로 씁니다.
- 원시 CSV는 `src/track_drive/track_drive/speed_calib_logs/`에 남아 있습니다.

결과적으로 speed 20부터는 견인력 포화로 비선형이었고, speed 25는 하드웨어 문제로 측정을 보류했습니다.

## 설계값 (실측 아님)

| 상수 | 값 | 비고 |
|---|---|---|
| `DL_PIXELS_PER_METER` | 200 | BEV 캔버스를 1m=200px로 **정의**한 값 |
| `PP_WHEELBASE_PX` | 30 (+부스트) | 튜닝 게인. 물리 계산값 67을 "정답"으로 착각해 되돌리지 말 것 |
| `PP_*` lookahead 계열 | [04](04-steering-control.md#최종값) 참고 | 시뮬레이터 + 실차 수동 튜닝 |
| `B2_TO_B3_DELAY_SEC` | 3.0 | 트랙 순서 가정에 의존 |
| `SHORTCUT_EXIT_DIST_M` / 킥 각도 | 5.5m / −20° | 체감 기반 |

## 카메라를 다시 달면

1. BEV 4점을 다시 찍고 `config.py`의 `DL_BEV_SRC_PX_RAW`를 갱신한다 (당시 쓴 `bev_point_picker.py`는 저장소에
   커밋되지 않았습니다)
2. 차량 중심 x좌표는 4점에서 자동 재계산된다. 하지만 4점이 정확한지(카메라가 차량 중심에 있는지)는 검증되지
   않으므로 직선 구간에서 조향 편향이 없는지 확인한다.
3. YOLO 박스 면적 임계값은 카메라 높이·각도에 따라 바뀌므로 다시 잰다.
